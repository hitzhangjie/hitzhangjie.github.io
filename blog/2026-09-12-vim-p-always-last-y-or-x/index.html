用了这么多年 Vim，才搞清 p 到底贴的是什么

Posted 2026-09-12 08:25 +0800 by ZhangJie ‐ 4 min read

分享:  

用 Vim 很多年了，y / p / x / dd 每天都在按，按出肌肉记忆了。但有一件事一直没真正想清楚：

y 复制一段代码，中间随手 dd 两行、cw 改个名字，再按 p——贴出来的经常不是刚才 yank 的内容。

2024 年写过一篇 Vim 复制粘贴丢内容？寄存器机制详解，结论是：默认 p 读的是无名寄存器 ""，而 y / d / c / x / s 都会写它。想保住 yank，粘贴用 "0p。

那篇把 x 也算进「会弄丢复制内容的操作」。后来发现这不是我想要的契约。真正想要的是：

不管 y 或 x 之后执行了什么，p 永远贴最近一次 y 或 x 的内容。

d / c / s 是编辑，不该抢剪贴板；x 是剪切，该和 y 一样成为 p 的来源。

下面把这套机制拆开。拆完之后，那几行 .vimrc 就不是玄学映射了。

先把按键分成两类意图 ##

很多人（包括用了很久的我）下意识把下面这些都当成「剪贴板操作」：

键实际在干什么原文还在吗会不会进插入模式
yyank，复制在否
x / X删当前 / 左边一个字符不在否
ddelete，删一段（dw / dd / d$ …）不在否
cchange，删一段然后进入插入模式（cw / cc …）不在是
ssubstitute，删当前字符然后进入插入模式（等价 cl）不在是

d / c / s 经常被混着说，其实只是「删」的三种外壳：

  • d：删完还在 Normal 模式
  • c：删完进入 Insert，接着打新的
  • s：c 的单字符快捷方式；大写 S 则是 cc（整行）

它们的共同点是：目的是改文本。删空行、改变量名、换一个词，过程中碰巧产生了一段「被删掉的文字」，但你通常并不打算稍后把这段文字贴到别处。

y 和 x 相反：目的就是拿到这段文字。y 是复制，x 是按字符剪切。xp 交换两个字符能成为肌肉记忆，正因为 x 的结果就是给 p 用的。

Vim 默认并不区分这两种意图。它把它们都写进同一个默认寄存器。这才是 p 经常「贴错」的根因。

默认的 p 贴的是无名寄存器 ##

Vim 没有一块叫 clipboard 的单一剪贴板，它有一排寄存器。和这次问题直接相关的就四个：

寄存器名字谁写它默认 p 读它吗
""无名寄存器（unnamed）最近一次 y / d / c / x / s是
"0yank 寄存器只有 yank（y / yw / yy / yiw …）否，除非你写 "0p
"-小删除寄存器不足一行的删除 / 修改（x、dw、d$、s …）否
"1–"9删除历史整行或大段删除（dd、跨行 d），每次往上挤一格否

查看方法：

:reg
:reg 0 " - 1

用一个最小实验就能看清楚。文件内容：

hello world
second line

光标在第一行行首，依次执行 yy、x、jdd，每次看寄存器：

yy    "" = "hello world\n"   "0 = "hello world\n"
x     "" = "h"               "0 不变          "- = "h"
jdd   "" = "second line\n"   "0 不变          "1 = "second line\n"
p     贴出的是 ""，也就是刚 dd 掉的那一行

y 的内容其实还在 "0 里，并没有丢。丢的是「默认 p 的指针」——它一直盯着 ""，而 "" 被后面的删除盖掉了。

这就是 2024 那篇给出 "0p 的原因：yank 有专用保险箱，删除进不去。

"0 不收 x，因为 x 在 Vim 里不是 yank ##

"0p 能保住 y，保不住 x。

Vim 把 x 实现成一次删除，不是一次 yank。对单字符来说，它走的是小删除路径：写入 "" 和 "-"，不写 "0，通常也不写 "1。

所以会出现这种别扭：

yw        "0 = 那个 word          ← yank，进保险箱
x         "0 仍然是那个 word      ← 刚剪掉的字符只在 "" 和 "-"
dd        "" 被整行覆盖
"0p       贴出的是 word，不是刚才 x 掉的字符
p         贴出的是 dd 的那一行

如果你把 x 当剪切用（我就是），"0p 这个「只保 yank」的方案是错的。它解决了 d / c / s 抢剪贴板，但也把 x 排除出了剪贴板。

TextYankPost 也帮不上忙。x 触发 hook 时，v:event.operator 是 d 不是 x，跟真的 dw / dd 区分不开。要让 x 进入 "0，只能映射 x / X 本身。

错误映射：noremap p "0p ##

最常见的「一劳永逸」是：

noremap p "0p

效果：裸 p 永远读 "0。y 之后无论 dd 还是 cw，p 都贴 yank。这已经覆盖了 80% 的「粘贴丢了」投诉。

两个洞：

  1. x 仍然不写 "0，所以 x 之后的 p 还是上一次 yank。
  2. 命名寄存器被掐死。你以为 "ap 是「从 a 贴」，实际键序变成 "a + "0p，还是从 "0 贴。noremap x "0x 同样会让 "ax 写到 "0 而不是 "a。

第 2 点是 noremap p "0p 这种硬前缀的通病：它把寄存器前缀写死了，用户稍后给的 "a 被吞掉。

正确契约：p 读 "0，y 和 x 都写 "0 ##

目标可以收成一句话：

  • 裸 p / P → 读 "0
  • 裸 y → 本来就会写 "0，不用改
  • 裸 x / X → 强制写 "0
  • "ap / "ax → 照旧走命名寄存器，不动 "0
  • d / c / s → 继续写 "" / "- / "1，不碰 "0

对应的映射：

" p/P always paste the last y or x (yank register "0).
" y already fills "0; other deletes/changes (d/c/s) do not.
" Map x/X into "0 as well so a character cut is what p pastes.
" Named registers ("ap, "ax, ...) are left unchanged.
noremap <expr> x (v:register ==# '"' ? '"0' : '"' . v:register) . 'x'
noremap <expr> X (v:register ==# '"' ? '"0' : '"' . v:register) . 'X'
noremap <expr> p (v:register ==# '"' ? '"0' : '"' . v:register) . 'p'
noremap <expr> P (v:register ==# '"' ? '"0' : '"' . v:register) . 'P'

v:register ==# '"' 表示这次按键没有显式指定寄存器，Vim 会把 v:register 设成无名寄存器的名字 "。这时我们改写到 "0。否则原样带上用户给的 "a、"b。

<expr> 的右侧不会再映射一遍（noremap），所以返回的 'x' / 'p' 走的是 Vim 原生命令，不会递归。

noremap 同时覆盖 Normal 和 Visual：可视选区里的 x 也会进 "0，这和「剪切」一致。

不要自己在表达式里再拼一份 v:count。把 count 写进 rhs 会和 Vim 已经吃掉的数字叠在一起，3x 可能变成删整行那种离谱结果。让 Vim 自己把 3 作用到最终的 x / p 上即可。

改完之后实际怎么走 ##

还是那份两行文件，光标在 hello world 行首。

操作序列"0 里是什么裸 p 贴什么
yy 然后 dd 然后 pyank 的那一行yank 的那一行
x 然后 dd 然后 p刚 x 掉的字符那个字符
yw 然后 x 然后 p刚 x 掉的字符那个字符（最近一次是 x）
x 然后 yw 然后 p刚 yank 的 word那个 word（最近一次是 y）
yiw 然后 cw 改词 然后 p原来的 word原来的 word（c 没抢）
3x三个字符三个字符，count 有效
"ap不动 "0贴的是寄存器 a
xp当前字符两个字符对调，老用法还在

最后一行值得单独说：xp 能换两个字符，靠的就是「x 写入默认粘贴源，紧接着 p 读同一个源」。把 x 和 p 都绑到 "0 上之后，这条肌肉记忆仍然成立。

和系统剪贴板不是一件事 ##

set clipboard=unnamed / unnamedplus 是另一层：把无名寄存器和操作系统剪贴板同步。

它解决的是 Vim ↔ 浏览器 / 终端 的互通，不解决「dd 会不会覆盖我刚才复制的东西」。打开之后，Vim 里一次 dd 往往连系统剪贴板一起洗掉——刚从浏览器 Ctrl-C 的 URL，进 Vim 删一行就没了。

所以我一直把这行注释掉。需要和系统互通时显式用 "+y / "+p。WSL 下还经常根本没有 clipboard 支持，那是另一条坑，这里不展开。

ps: 2024 那篇把命名寄存器、"+ / "*、clipboard=unnamed 的取舍写过了。本文只补一件事：p 的来源应该是「最近一次复制或剪切」，不是「最近一次碰巧删掉的文本」。

怎么确认自己机器上的 Vim 就是这样 ##

最小检查，不依赖任何配置：

:enew
:call setline(1, ['abcdefg', 'ABCDEFG'])
:let @0 = 'OLD'
:normal! yy
:echo 'after yy  0=' . strtrans(@0)
:normal! x
:echo 'after x   0=' . strtrans(@0) . '  unnamed=' . strtrans(@") . '  -=' . strtrans(@-)

未改映射时，x 之后 "0 仍是 yy 的那一行，x 掉的字符在 "" 和 "-。加上面那组映射后再 x，"0 会变成那个字符。

日常看现场用 :reg 0 " - 1 就够。插入模式里贴 "0，是 Ctrl-R 再按 0。

收束 ##

Vim 的 p 并不「记住你刚才复制了什么」，它只读当前默认寄存器。默认寄存器被设计成「最近一次 yank 或 delete 或 change」——对 Vi 兼容是对的，对「复制 / 剪切 vs 编辑」这种现代直觉是错的。

一旦接受这个区分，配置就只剩两步：

  1. 让裸 p 读 yank 保险箱 "0（d / c / s 进不去）
  2. 让 x / X 也写入 "0（剪切和复制平权）

命名寄存器继续用 "a 前缀，系统剪贴板继续用 "+。三套东西各管各的，不要用 clipboard=unnamed 揉成一块。
