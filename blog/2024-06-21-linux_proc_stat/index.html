Linux /proc/stat：CPU 字段含义与更新方式

Posted 2024-06-21 00:00 +0800 by ZhangJie ‐ 3 min read

分享:  

top、mpstat、各类 agent 算 CPU 利用率，几乎都绕不开 /proc/stat。字段看着简单，顺序一旦记错，steal 和 softirq 就会对调；更新机制若理解成「定时器 250Hz 写文件」，后面排障也会偏。

本文只盯 cpu / cpuN 行：各列是什么、内核在哪记账、读路径怎么吐出来，以及虚拟化下的 steal。

进程级 utime/stime、tick catchup 与 sum_exec_runtime 的关系，见 Linux 进程 CPU 时间记账。这里只讲整机 / 每核那本账。

一、字段：十列从左到右 #

示例：

$ cat /proc/stat
cpu  3528219 41639 1261361 2231716632 130444 0 261512 0 0 0
cpu0 143880 243 62282 92967749 9757 0 193767 0 0 0
...

cpu 是所有逻辑核累加；cpuN 是单核。单位是 jiffies（累计值，从开机起加，不归零）。列顺序固定：

列序名字含义
1user用户态（nice 优先级正常）
2nice用户态且 nice > 0
3system内核态（不含单独拆出的 irq/softirq）
4idle空闲
5iowait有任务在等 IO 时的 idle（语义有历史包袱，见下）
6irq硬中断处理
7softirq软中断处理
8steal虚拟化下被 hypervisor 偷走、本 guest 用不了的时间
9guest跑 guest 虚拟机（KVM 等）的用户态时间
10guest_niceguest 且 nice 的时间

对上面那行：

user=3528219  nice=41639  system=1261361  idle=2231716632
iowait=130444  irq=0  softirq=261512  steal=0  guest=0  guest_nice=0

常见记错：把第 6 列当 steal、第 7 列当硬中断。正确是 irq → softirq → steal。

算利用率时，增量要先做两次采样的差分。粗算 busy：

busy = user + nice + system + irq + softirq + steal + guest + guest_nice
total = busy + idle + iowait
util% ≈ 100 * Δbusy / Δtotal

guest / guest_nice 在 host 上已经从 user / nice 里扣过再单独列，避免双重计算时要小心工具实现。

iowait 容易误解：它不是「磁盘在干活」，而是 CPU 空闲且该 CPU runqueue 上有任务在等 IO。多核、异步 IO、短睡眠都会让这个数和直觉不一致；排 IO 瓶颈时别只盯这一列。

二、账记在哪：不是「写 /proc/stat」 #

内核不会定时把统计刷进某个「/proc/stat 文件」。/proc/stat 是伪文件，读的时候才从 per-CPU 计数器拼出文本（fs/proc/stat.c 的 show_stat）。

真正的累加发生在运行路径上，主要是 tick 记账。

路径（简化）：

tick_handle_periodic / tick_sched_timer
  → tick_periodic / tick_sched_handle
    → update_process_times
      → account_process_tick
        → account_user_time / account_system_time / account_idle_time ...

每个 tick，内核看当前 CPU 在干什么，给对应桶加 TICK_NSEC（HZ=1000 时约 1ms）：

  • 用户态 → user 或 nice
  • 内核态 → system（再细分 irq / softirq 时走对应路径）
  • 空闲 → idle 或 iowait
  • 被 steal 扣掉的部分 → 先减再分摊，见下一节

累计存在 kcpustat（per-CPU） 一类结构里，例如：

// 概念示意，字段名随版本略有差异
enum cpu_usage_stat {
    CPUTIME_USER,
    CPUTIME_NICE,
    CPUTIME_SYSTEM,
    CPUTIME_SOFTIRQ,
    CPUTIME_IRQ,
    CPUTIME_IDLE,
    CPUTIME_IOWAIT,
    CPUTIME_STEAL,
    CPUTIME_GUEST,
    CPUTIME_GUEST_NICE,
    ...
};

account_user_time / account_system_time 等会同时：

  1. 给当前进程的 utime / stime 加一截（进程账）
  2. 给本 CPU 的 kcpustat[CPUTIME_*] 加一截（整机/每核账）

读 /proc/stat 时，show_stat 遍历各 CPU 的 kcpustat，换算成 jiffies 打出来。所以：

  • 更新：事件/tick 路径上改计数器
  • 展示：用户 read() 时拼字符串
  • 不是：定时器每 4ms 重写一遍 /proc/stat

上下文切换次数、进程创建数、中断总数等同文件里其他行，也是各自路径上的计数器，读时再汇总——机制同类。

ps: 早期对话里容易把「模式切换时记账」和「定时器触发写文件」搅在一起。用户态↔内核态切换会改 task 上下文，但 CPU 桶的主增量仍是 tick 采样；VIRT_CPU_ACCOUNTING_GEN 等配置下还有更细的 sched clock 路径，那是另一条实现，语义仍是往同一套 kcpustat 里加。

三、steal：被 hypervisor 拿走的时间 #

裸机上 steal 通常是 0。虚拟机里，物理核要在多个 vCPU / host 进程之间切：当前 guest 的 vCPU 被 deschedule 掉的那段墙钟时间，对 guest 来说就是 本该能用却没用上的 CPU，记为 steal。

guest 侧怎么知道「被偷了多久」？靠 半虚拟化接口，不是 guest 自己猜：

  1. hypervisor 维护该 vCPU 被抢走的累计时间（steal clock）
  2. guest 通过 paravirt / steal_clock 一类接口读增量
  3. tick 记账里 steal_account_process_time() 先把 steal 扣掉，剩余再分给 user/system/idle

概念上：

// account_process_tick 里（简化）
cputime = TICK_NSEC;
steal   = steal_account_process_time(...);  // 读 steal clock 增量，写入 CPUTIME_STEAL

if (steal >= cputime)
    return;                 // 这一个 tick 全被偷走了

cputime -= steal;
// 再按 user / system / idle 分摊 cputime

所以 steal 不是「guest 里某个进程在跑时突然 +Δt」那么简单，而是：vCPU 停摆期间累计的不可用时间，在 guest 恢复跑、处理 tick 时灌进 CPUTIME_STEAL。guest 内部只看到累计值变大，看不到 host 上具体是谁抢走了核。

监控含义直接：

  • steal 持续偏高 → 母机争用 / 超卖 / 绑核不合理
  • 同一时刻 guest 里 top 显示 CPU 不高，但业务延迟差，值得先看 steal 和母机负载

四、和进程 CPU 账的关系 #

/proc/stat 的 cpu 行/proc/pid/stat 的 utime/stime
对象整机 / 每核单个任务
主路径同一套 account_*_time → kcpustat同一路径 → task->utime/stime
读时修正基本直接吐累计新内核可有 cputime_adjust 对齐调度器时间

两边同源：都是 tick（或等价 accounting）时看「当前在干啥」。差别是聚合粒度，以及进程侧后来加了和 sum_exec_runtime 的对齐。虚拟化下 tick catchup 会把进程 tick 账灌爆，整机 kcpustat 同样会在 catchup 循环里被反复 account_*——那是另一篇已经拆过的坑。

五、实践上怎么读 #

# 两次采样，自己做差分（别直接看绝对值）
grep '^cpu ' /proc/stat; sleep 1; grep '^cpu ' /proc/stat

# steal 一眼
awk '/^cpu /{print "steal="$9, "softirq="$8, "irq="$7}' /proc/stat

# 和进程账对照（异常 CPU% 时）
cat /proc/$(pidof your_app)/stat | awk '{print "utime="$14,"stime="$15}'
cat /proc/$(pidof your_app)/sched | grep sum_exec_runtime

工具侧注意：

  1. 列序不要记错，尤其 softirq / steal
  2. 利用率一定用 Δ，窗口太短会抖
  3. 云主机看业务慢时，steal 和 user 一样该进面板
  4. 需要纳秒级真实执行时间时，进程侧看 sum_exec_runtime / perf，不要只信 tick 采样

小结 #

/proc/stat 的 cpu 行是 per-CPU kcpustat 的 jiffies 快照，十列语义固定，读时拼装，不是定时写文件。时间在 tick 记账路径上按当前上下文分桶；虚拟化下 steal 来自 hypervisor 的 steal clock，在 guest tick 里扣进 CPUTIME_STEAL。字段记清、差分算对，再和进程级两套账对照，排「CPU 很高 / 业务很慢」类问题时会少走很多弯路。
