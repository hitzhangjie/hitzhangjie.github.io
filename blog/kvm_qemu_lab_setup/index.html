Linux KVM/QEMU 虚拟化实验环境搭建 #

以 WSL2 为宿主机，搭建多实例 KVM 实验环境，用于验证 clocksource、steal time 等虚拟化行为。

一、环境检查 ##

WSL2 上先确认硬件虚拟化和 KVM 是否可用：

# 1. CPU 虚拟化支持（Intel VT-x 为 vmx，AMD-V 为 svm）
grep -E 'vmx|svm' /proc/cpuinfo | head -1

# 2. /dev/kvm 设备是否存在且可读写
ls -la /dev/kvm

# 3. 内核 KVM 模块是否编译
zgrep CONFIG_KVM /proc/config.gz

我这边的输出：

flags: ... vmx ... ept vpid ept_ad ... constant_tsc nonstop_tsc tsc_known_freq tsc_reliable ... tsc_deadline_timer ... hypervisor ...

/dev/kvm: crw-rw-rw- 1 root kvm 10, 232

CONFIG_KVM=y
CONFIG_KVM_INTEL=y
CONFIG_KVM_AMD=y

关键 flag 解读：

  • vmx：Intel VT-x 支持，嵌套 KVM 的硬件基础
  • ept vpid ept_ad：Extended Page Table 相关，说明这是一台功能完整的虚拟化平台
  • constant_tsc nonstop_tsc tsc_known_freq tsc_reliable：四个 flag 组合等价于 invariant TSC——不受频率变化/C-state 影响、频率已知可信，是裸 tsc 能被选为 clocksource 的底层原因
  • tsc_deadline_timer：Local APIC Timer 支持 TSC-deadline 模式
  • hypervisor：CPUID 标明运行在虚拟化环境下（Hyper-V 传入，印证 WSL2 = Hyper-V guest）

/dev/kvm 权限 crw-rw-rw-，所有用户可读写，无需额外加 kvm 组。

二、安装 QEMU ##

sudo apt update
sudo apt install -y qemu-system-x86 qemu-utils cloud-image-utils

如果宿主机是 CentOS/RHEL，对应命令为 sudo yum install -y qemu-kvm qemu-kvm-core qemu-img genisoimage，后续 QEMU 启动命令中的 qemu-system-x86_64 替换为 qemu-kvm 即可。

三、创建第一台虚拟机 ##

这里提供 CentOS 7（内核 3.10）和 CentOS 8 Stream 两种方案，按需选择。

3.1 方案 A：CentOS 7 ##

mkdir -p ~/kvm-lab && cd ~/kvm-lab

# 下载云镜像
wget https://cloud.centos.org/centos/7/images/CentOS-7-x86_64-GenericCloud.qcow2

# cloud-init 配置（含 EOL 后的 vault 源切换）
cat > user-data <<'EOF'
#cloud-config
password: kvmlab
chpasswd: { expire: False }
ssh_pwauth: True

bootcmd:
  - sed -i 's/^mirrorlist/#mirrorlist/g' /etc/yum.repos.d/CentOS-*.repo
  - sed -i 's|^#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|g' /etc/yum.repos.d/CentOS-*.repo
EOF
cloud-localds seed.img user-data

# 扩容并启动
qemu-img resize CentOS-7-x86_64-GenericCloud.qcow2 8G

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host \
  -drive file=CentOS-7-x86_64-GenericCloud.qcow2,format=qcow2 \
  -drive file=seed.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

3.2 方案 B：CentOS 8 Stream ##

mkdir -p ~/kvm-lab && cd ~/kvm-lab

# 下载云镜像（如果文件名过期，先列目录确认）
wget https://cloud.centos.org/centos/8-stream/x86_64/images/CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2

# cloud-init 配置（CentOS 8 用 genisoimage 生成 seed）
cat > user-data <<'EOF'
#cloud-config
password: kvmlab
chpasswd: { expire: False }
ssh_pwauth: True
EOF

cat > meta-data <<'EOF'
instance-id: kvmlab01
local-hostname: kvmlab
EOF

genisoimage -output seed.img -volid cidata -joliet -rock user-data meta-data

# 扩容并启动
qemu-img resize CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2 8G

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host \
  -drive file=CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2,format=qcow2 \
  -drive file=seed.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

3.3 登录验证 ##

CentOS 云镜像默认用户为 centos，首次启动 cloud-init 会执行 SELinux relabel、生成 SSH host key 等，耐心等待 1-2 分钟。

ssh -p 2222 centos@localhost   # 密码 kvmlab

进去后跑验证命令：

uname -r
cat /sys/devices/system/clocksource/clocksource0/current_clocksource
cat /sys/devices/system/clocksource/clocksource0/available_clocksource
dmesg | grep -i -E "kvm|clocksource"

四、创建第二台虚拟机 ##

第二台虚拟机需要独立的磁盘和独立的端口，即使用同一份 base image 也不能直接复用同一个 qcow2 文件（两边都当自己是唯一写者，会导致磁盘损坏）。

4.1 磁盘复制：两种方式 ##

方式 A：完整复制（简单，占空间）

mkdir -p ~/kvm-lab/instance2 && cd ~/kvm-lab/instance2

# 直接 cp 一份完整磁盘
cp ../CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2 instance2.qcow2
qemu-img resize instance2.qcow2 8G

方式 B：backing file 增量镜像（推荐，省空间、更快）

mkdir -p ~/kvm-lab/instance2 && cd ~/kvm-lab/instance2

# 基于 base image 创建增量镜像，只存差异数据
qemu-img create -f qcow2 \
  -b ../CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2 \
  -F qcow2 \
  instance2.qcow2 8G

推荐的流程：先按第三节完整配置好第一台虚拟机（安装必要软件包、配置好环境），确认一切正常后关机，再用方式 B 基于第一台的磁盘创建增量镜像作为第二台。这样第二台启动后直接就是"已配置好"的状态，不需要重复装软件、改源等操作。

4.2 第二份 seed 盘 ##

建议修改 hostname 方便区分：

# 复用同一个 user-data（密码策略不变），只改 meta-data
cat > meta-data <<'EOF'
instance-id: kvmlab02
local-hostname: kvmlab2
EOF

genisoimage -output seed2.img -volid cidata -joliet -rock user-data meta-data

4.3 启动第二台（端口必须换） ##

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host \
  -drive file=instance2.qcow2,format=qcow2 \
  -drive file=seed2.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2223-:22 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

关键差异：

  • 磁盘用第二台的独立 qcow2
  • seed 用 seed2.img
  • hostfwd 端口换成 2223（不换会跟第一台冲突）
  • 登录：ssh -p 2223 centos@localhost

-nographic 模式下两个实例各占一个终端，建议用 tmux/screen 管理。

4.3 多实例管理速查 ##

实例磁盘seedSSH 端口
VM1CentOS-Stream-...qcow2seed.img2222
VM2instance2.qcow2seed2.img2223

五、实例的停止与重启 ##

停止 ##

# 方法 1：SSH 进 guest 优雅关机
ssh -p 2222 centos@localhost sudo poweroff

# 方法 2：直接发 SIGTERM（推荐，无需登录）
kill $(pgrep -f "hostfwd=tcp::2222")

# 方法 3：前台运行时按 Ctrl+A 再按 X

重启（复用已有磁盘和 seed，只改启动参数） ##

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host \
  -drive file=CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2,format=qcow2 \
  -drive file=seed.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

要点：

  • 磁盘和 seed 路径保持不变，数据都在
  • 多实例时 hostfwd 端口和 seed 要对上号
  • 用了 backing file 的实例，-drive file= 用增量镜像路径即可，base image 自动通过 backing file 引用

六、进阶用法 ##

6.1 开放更多端口（host → guest 端口转发） ##

QEMU user-mode 网络（SLIRP）默认将 guest 放在 NAT 后面，host 无法直接访问 guest 内启动的服务。如果要在 guest 内启动 TCP server 并从 host 访问，需要在 -netdev 中添加额外的 hostfwd 规则。

语法：hostfwd=tcp::<host_port>-:<guest_port>，多个规则用逗号分隔。

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host \
  -drive file=CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2,format=qcow2 \
  -drive file=seed.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2222-:22,hostfwd=tcp::8080-:8080,hostfwd=tcp::9090-:9090 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

上面示例开放了三个端口：

host 端口guest 端口用途
222222SSH
80808080HTTP / 应用服务
90909090自定义 TCP 服务

guest 内启动服务后，host 即可直接访问：

# guest 内
python3 -m http.server 8080 &
nc -l 9090 &

# host 访问
curl localhost:8080
echo "hello" | nc localhost 9090

注意：host 端口之间不能冲突，也不能和 host 已有服务端口冲突。如果 QEMU 已启动后想新增端口转发，只能停掉重新带新参数启动（可按第五节的重启流程操作，磁盘数据不会丢失）。

6.2 触发 steal time ##

需要制造 host 层面的 CPU 争抢才能看到非零的 steal time。单纯起第二个闲置 guest 看不到效果。

有效做法：

  1. 明确 WSL2 环境总共给了多少 vCPU（nproc）
  2. 让所有 guest 的 -smp 之和明显超过这个核数，制造真实的资源争抢
  3. 在其中一个 guest 里跑 CPU 密集负载，同时观察另一个 guest 的 /proc/stat 中 steal 字段

两种具体手段都已验证可行：

  • 母机跑满核心：在 WSL2 中 yes > /dev/null & 跑满所有核，和 guest 争抢
  • taskset 绑定核心：把所有 QEMU 实例绑定到相同的几个核心上
# 查看 steal time
watch -n1 "head -1 /proc/stat | awk '{print \$9}'"
# top 中看 st 列
top

6.3 禁用 steal time 上报（模拟云厂商行为） ##

KVM guest 的 steal time 通过 kvm-steal-time paravirt CPU feature 实现。去掉这个 feature 即可隐藏上报：

qemu-system-x86_64 \
  -enable-kvm \
  -m 2048 \
  -smp 2 \
  -cpu host,-kvm-steal-time \    # ← 减号去掉 kvm-steal-time
  -drive file=CentOS-Stream-GenericCloud-8-latest.x86_64.qcow2,format=qcow2 \
  -drive file=seed.img,format=raw \
  -netdev user,id=net0,hostfwd=tcp::2222-:22 \
  -device virtio-net-pci,netdev=net0 \
  -nographic

启动后 guest 内验证：/proc/stat 的 steal 列应始终为 0。

注意：-kvm-steal-time 只是隐藏了 steal time 的上报，vCPU 被 host 调度器 deschedule 的事实不会变。当 guest 被长时间停掉后 resume，timer catchup 仍会将积压的 ticks 集中注入进程记账——这恰好复现了云厂商超卖场景下 PerCore% 破 100% 的根因。

七、补充：软件源问题 ##

RHEL 7 / CentOS 7 / CentOS 8 Stream 官方已停止维护，对应的 mirrorlist 已下线。首次登录后务必先修复软件源，否则 yum/dnf 无法正常使用：

sudo sed -i 's/^mirrorlist/#mirrorlist/g' /etc/yum.repos.d/CentOS-*.repo
sudo sed -i 's|^#baseurl=http://mirror.centos.org|baseurl=http://vault.centos.org|g' /etc/yum.repos.d/CentOS-*.repo
sudo yum clean all && sudo yum makecache
